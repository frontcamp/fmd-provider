
Не использовать повествование от первого лица и прямые обращения к читателю. Участников процесса обозначать по ролям: пользователь (приложения), администратор, приложение. Исключение: инструкции для ИИ-агента могут содержать прямую речь в виде команд: "используй то-то", "делай так-то" и т.п.

Стиль текста документа - лаконичный, технический. Отдавать предпочтение простым прямым формулировкам, без сложных речевых оборотов. Рядом с требованиями допускаются короткие произвольные пояснения, чтобы позже можно было понять, что послужило причиной появления данного требования.

### Тегование

Для выделения ключевых тезисов рекомендуется использовать теги:

```markdown

ПРАВИЛО: текст правила.

ТРЕБОВАНИЕ: текст требования.

ИСКЛЮЧЕНИЕ: текст исключения.

ПРИМЕЧАНИЕ: текст примечания.

```

Если тезисов несколько, использовать нумерацию:

```markdown

ПРАВИЛО 1: текст первого правила.

ИСКЛЮЧЕНИЕ 1: текст первого исключения из первого правила.

ИСКЛЮЧЕНИЕ 2: текст второго исключения из первого правила.

ПРАВИЛО 2: текст второго правила.

ИСКЛЮЧЕНИЕ: единственное исключение из второго правила.

ПРИМЕЧАНИЕ 1: первое примечание ко второму правилу.

ПРИМЕЧАНИЕ 2: второе примечание ко второму правилу.

```

Нумерация правил начинается в каждом разделе.
Исключения и примечания относятся к непосредственно предшествующему правилу или требованию. Их нумерация ведется отдельно в пределах этого правила или требования.

Допускается создавать другие теги, в зависимости от контекста.
