Назначение документа
--------------------

Документ определяет правила создания, оформления и проверки навыков ИИ-агента. Предназначен для пользователей и ИИ-агентов, выполняющих эти задачи.


Содержание
----------

- Создание и оформление навыка
- Ресурсы навыка
- Проверка навыка


Создание и оформление навыка
----------------------------

Критерии создания навыка:

1. Специализация. Инструкции относятся к определённому классу задач.
2. Переиспользование. Компетенция требуется многократно.
3. Автономность. Навык имеет понятные границы и может развиваться независимо.
4. Ценность. Навык должен улучшать результат по сравнению с работой агента без него.

### Именование навыка

Имя навыка должно соответствовать формату "kebab-case":

1. От 1 до 64 символов.
2. Строчные латинские буквы (a-z), цифры и дефисы.
3. Без пробелов, подчёркиваний и двойных дефисов.
4. Дефис не может стоять в начале или конце.
5. Значение поля `name` должно совпадать с именем каталога навыка.

Рекомендованный принцип именования: `<объект>-<действие>`.

Примеры: `code-review`, `document-translation`, `text-summarization`, `cat-detection`, `universe-debugging`.

Нерекомендуемые имена:

- programming - слишком широкое;
- helper - непонятное назначение;
- coding-tools - описывает инструменты, а не компетенцию;
- best-practices - не определяет область применения.

### Метаданные навыка

Файл `SKILL.md` должен начинаться с YAML-заголовка, содержащего обязательные поля:

- `name` - идентификатор навыка, соответствующий правилам именования.
- `description` - описание назначения навыка и условий его применения (не более 1024 символов).

После YAML-заголовка файл `SKILL.md` должен содержать инструкции в формате Markdown.

Поле `description` заголовка должно:

1. Конкретно указывать, какие задачи решает навык.
2. Определять ситуации, в которых навык следует применять.
3. Содержать характерные ключевые слова для определения применимости навыка.
4. Не содержать общих и неоднозначных формулировок.
5. При необходимости указывать ситуации, в которых навык применять не следует.

### Оформление инструкций

Форма изложения и внутренняя структура инструкций выбираются по эффективности применения инструкций ИИ-агентом.

Из инструкций ИИ-агенту должны быть понятны требуемые действия, условия их выполнения, область действия и исключения. Рекомендуется использовать теги (`ПРАВИЛО:`, `ИСКЛЮЧЕНИЕ:`, `ПРИМЕЧАНИЕ:` и др.) для структурирования и формализации инструкций.

Допускаются редакторские примечания с тегами `ПОЯСНЕНИЕ:` или `РАЗЪЯСНЕНИЕ:`. Они служат для объяснения причин принятия тех или иных решений и не должны противоречить инструкциям.

### Учет этапов внедрения

**Назначение**

Механизм рекомендуется использовать для учёта редакционной готовности и практической проверенности отдельных блоков инструкций независимо от общей завершенности документа.

**Терминология**

- **Внедрение** - процесс разработки, проверки и закрепления блока инструкций в практическом применении.
- **Этап внедрения** - стадия процесса внедрения с установленными критериями редакционной готовности или практического подтверждения.
- **Статус внедрения** - значение, присвоенное конкретному блоку и указывающее его текущий этап внедрения.
- **Маркер статуса** - символ, которым статус обозначается в документе.

**Перечень этапов**

- `[~]` - набросок - первичная формулировка идеи
- `[-]` - черновик - содержание активно дорабатывается
- `[+]` - рабочая версия - проверка применимости, стиля и грамотности
- `[$]` - стабильная версия - успешно применена минимум в одном проекте
- `[!]` - финальная версия - успешно применена минимум в двух проектах

Первые три статуса `<~|-|+>` отвечают за редакционную готовность блока инструкций. Последние два статуса `<$|!>` отвечают за его практическое подтверждение.

**Формат**

```Markdown
[ ] Заголовок второго уровня
----------------------------

### [ ] Заголовок третьего уровня

[ ] **Подзаголовок**

<!--
@comment 2026-11-08 by Maksym
Редакционный комментарий к правилу от автора Maksym.
@review 2026-11-09 passed, status up
@review 2026-11-10 passed, status down
-->
```

Маркер статуса и HTML-комментарий являются редакторскими метаданными блока инструкций. HTML-комментарий относится только к ближайшему предшествующему маркеру статуса.

HTML-комментарий не должен содержать информацию, которую ИИ-агент может трактовать как указания, изменяющие смысл инструкций блока. Комментарий предназначен исключительно для редакторских целей и фиксации истории изменения статусов. Следует периодически очищать или удалять эти комментарии, оставляя только существенные для будущих редакций или состояний.

**Границы и вложенность**

Блок продолжается до следующего заголовка или подзаголовка того же или более высокого уровня. Допускается вложение блоков. Внешний блок не должен находиться на более позднем этапе, чем любой из вложенных блоков.

ПРИМЕЧАНИЕ: Подзаголовок - текст на отдельной строке, выделенный жирным (`**...**`).

**Изменение статусов**

Решение об изменении статуса блока инструкций принимает редактор. При существенном изменении содержания блока его практическое подтверждение пересматривается. Редактор определяет новый статус с учётом характера изменений.


Ресурсы навыка
--------------

Организация навыка в виде каталога позволяет в нём размещать вспомогательные файлы, которые ИИ-агент может использовать по необходимости.

Рекомендуемая файловая структура навыка:

```
skills/
    <skill_name>/ - каталог навыка
        SKILL.md - основные инструкции навыка
        references/ - дополнительные знания, правила, справочники
        scripts/ - исполняемые программы
        assets/ - прочие ресурсы
```

Рекомендуется разделять инструкции навыка по отдельным подключаемым файлам, чтобы сократить объем избыточного контекста ИИ-агента за счет прогрессивной загрузки (при которой материалы загружаются по мере необходимости).


Проверка навыка
---------------

Перечень критериев качества:

1. Валидность. Соответствие стандарту Agent Skills.
2. Применимость. Корректность определения условий использования.
3. Полнота. Покрытие необходимых сведений и действий для выполнения задач навыка.
4. Однозначность, проверяемость и непротиворечивость.
5. Специализация. Соблюдение границ компетенции.
6. Эффективность. Отсутствие избыточных инструкций, рациональность использования контекста и отсутствие неоправданно сложных процедур.
7. Автономность. Достаточность информации для выполнения задач.
8. Безопасность. Отсутствие нежелательных действий.

### Проверка потенциальных проблем

Если пользователь просит оценить или проверить качество навыка, ИИ-агент должен проанализировать исследуемый навык, учитывая его назначение, и дать экспертное заключение (опираясь на рекомендации признанных экспертов или крупных IT/AI-компаний) по каждому критерию из списка выше. Для каждого несоответствия указать конкретный фрагмент, возможную ошибку или потенциальное затруднение и ожидаемую пользу изменения. Если проблему нельзя обосновать - правку не предлагать.

### Практическое выявление проблем

Если использование субагентов в текущей среде невозможно, сообщить пользователю об этом и прекратить выполнение практической проверки.

Если пользователь просит оценить практическую применимость навыка, действовать в соответствии с общей практикой использования субагентов:

- Выделить критические или спорные требования и подготовить задачи с заранее определёнными критериями успеха с учётом применимых критериев качества.
- Передать исполнителю навык, необходимые материалы и обычное задание, без переписки с разбором предполагаемой ошибки.
- Получить фактический результат: ответ, созданные файлы, выполненные действия.
- Сопоставить результат с критериями и в виде списка перечислить нарушения.

### Предложения по улучшению

Если пользователь спрашивает, что можно улучшить в навыке, ИИ-агент должен найти в сети аналоги в авторитетных источниках (рекомендации признанных экспертов или крупных IT/AI-компаний), сравнить с проверяемым навыком и дать экспертные вариативные рекомендации по улучшению на основании этого сравнения.
