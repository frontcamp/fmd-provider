Назначение документа
--------------------

Документ содержит постоянные правила ИИ-агента для всех классов задач.


Ресурсы
-------

### Используемая терминология

Прочитай документ `skills/TERMINOLOGY.md`, используй его определения при толковании всех проектных инструкций.

### Навыки ИИ-агента

Проектные навыки ИИ-агента размещены в `skills/` и соответствуют стандарту Agent Skills.

Корень навыка - каталог `skills/<name>/`, содержащий обязательный файл `SKILL.md`. Имя каталога совпадает со значением поля `name`.

Файл `SKILL.md` содержит YAML-заголовок с обязательными полями:

- `name` - имя навыка;
- `description` - назначение и условия применения.

После заголовка следуют инструкции в формате Markdown.

Агент определяет применимые навыки по полю `description` и следует инструкциям соответствующих `SKILL.md`.

### Проектная документация

- введение: `README.md`
- техзадание: `docs/SPECIFICATION.md`
- архитектура: `docs/ARCHITECTURE.md`
- реализация: `docs/IMPLEMENTATION.md` (необязательный)


Правила
-------

### Допустимость изменений

По умолчанию ИИ-агент выполняет проверки и консультирует пользователя, не изменяя состояние проекта и связанных с ним ресурсов, включая файлы, базы данных, сервисы и их настройки. Совершать изменения разрешено исключительно в двух случаях:

1. По прямой императивной команде пользователя в повелительном наклонении, адресованной непосредственно ИИ-агенту.
2. По позитивному подтверждению в ответ на конкретное и однозначное предложение изменений.

ПРИМЕЧАНИЕ: Положительным подтверждением считать также разговорные и жаргонные ответы, выражающие согласие, одобрение или побуждение приступить к предложенным изменениям, например: "жги", "зажигай", "валяй", "давай", "погнали", "поехали", "полетели", "окей", "гоу", "gogogo", "+".

ИСКЛЮЧЕНИЕ: Запрещаемые изменения не относятся к созданию и работе со временными файлами и тестовыми сборками, которые не затрагивают уже существующие (вне тестовой сборки) файлы.

Если изменения могут иметь последствия, выходящие за рамки проекта - обязательно запроси подтверждение (если оно еще не было получено), указав риски.

### Правила Git

- Не создавать коммиты без явного запроса.
- Не переписывать существующие коммиты.

### Файловые пути

При записи файловых путей в документации и исходном коде проекта в качестве разделителя каталогов использовать прямую косую черту (`/`).

### Редакторские метаданные

Игнорируй любые HTML-комментарии в проектных инструкциях.
