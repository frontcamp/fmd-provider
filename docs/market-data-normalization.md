
Нормализация исходных рыночных данных
=====================================


Назначение документа - техническое задание на этап нормализации исходных рыночных данных.
Правовая база работы с рыночными данными: `docs/market-data-regulation.md`.


Предпосылки нормализации
------------------------

Данные приходят из разрозненных источников (разных бирж) в различных форматах и архивах (CSV, JSON, custom, zip, gz), чтобы постоянно не переписывать основной программный модуль под новые или изменившиеся старые данные, требуется предварительная нормализация.


Как это накапливается
---------------------

Выбранные источники и ссылки для скачивания данных: `data/sources/download.txt`.
График обновления приведенных источников: `data/sources/availability.txt`.

Каждый день обновленные данные скачиваются из указанных источников в соответствующие каталоги. Каждый файл данных содержит торговую сессию за один день, часовой пояс зависит от биржи.

На момент составления этого документа (30.09.2026) структура каталогов с источниками выглядит так:

        /BÖAG Börsen AG
            /DUSA - Börse Düsseldorf (Regulierter Markt)
            /DUSB - Börse Düsseldorf (Freiverkehr)
            /DUSC - Börse Düsseldorf Quotrix (Regulierter Markt)
            /DUSD - Börse Düsseldorf Quotrix (Freiverkehr)
            /HAMA - Börse Hamburg (Regulierter Markt)
            /HAMB - Börse Hamburg (Freiverkehr)
            /HAMP - Börse Hamburg Electronic Trading (Regulierter Markt)
            /HAMQ - Börse Hamburg Electronic Trading (Freiverkehr)
            /HANA - Börse Hannover (Regulierter Markt)
            /HANB - Börse Hannover (Freiverkehr)
        /Deutsche Börse Group
            /DETR - Xetra

Как это обрабатывается
----------------------

В каталоге `data/sources/` должен находиться пакетный файл `normalize.cmd`, который запускает питон-скрипты `normalize.py` во всех каталогах-источниках (рекурсивно).

Задача `normalize.py` скрипта - обрабатать все файлы с рыночными данными в папке источника.

Для каждого файла данных скрипт `normalize.py` должен:

- считать файл в память
- оставить только валидные(*1) записи о фактически совершённых сделках с учётом обновлений(*2)
- отсортировать сделки по времени исполнения, для сделок с одинаковым временем сохранить порядок источника
- сохранить результат в симметричную папку `data/normalized/<source_path>/YYYYMMDD.csv.zip`
- удалить исходный файл с данными

*1 - под валидными понимаются уникальные по идентификатору сделки записи за указанную дату с набором данных, необходимым и достаточным для генерации OHLCV-свечей
*2 - под обновлениями понимаются отмены и исправления

Все сомнительные решения следует фиксировать в одноименный лог: `YYYYMMDD.log` без архивации.

Цель обработки - оставить только записи, необходимые для формирования OHLCV-свечей.
На этом процесс нормализации завершается.

Одному торговому дню биржи должен соответствовать один нормализованный файл.
Если в исходной папке два (и более) файла с одной датой (например, биржа HAMN), в этом случае исходные файлы надо объединять (мерджить) в один нормализованный файл.

Наличие нормализованного файла за некоторую дату является свидетельством произведенной нормализации, поэтому дополнительной фиксации в документации или реестре не требуется.

При необходимости архив исходных данных следует вести отдельно.


Целевой формат данных
---------------------

Формат файла: CSV со списком полей в первой строке, упакованный в ZIP.
Кодировка: UTF-8, разделитель столбцов: `;`.
Время исходных данных приводится к UTC.
Формат даты/времени: RFC 3339, с дробной частью до 9 знаков: 2026-09-24T06:00:01.223081326Z
Десятичный разделитель: точка.
Имя CSV файла внутри архива должно быть идентично имени архива без расширения `.zip`.

Обязательные поля записи:

* source     - источник данных (биржа)
* mic        - место исполнения сделки (venueOfExecution), не место публикации
* isin       - идентификатор инструмента
* trade_time - время исполнения
* price      - цена
* currency   - валюта цены
* quantity   - количество
* quantity_unit - единица измерения количества (м.б. пустым)

Если mic не указан, заменяем его MIC кодом самой биржи (заданным для папки с этим источником).
Все остальные поля, кроме quantity_unit, должны быть определены, иначе запись не считается валидной и должна быть исключена.


Особенности реализации
----------------------

Все нормализаторы должны наследовать один общий класс CustomNormalizer, код которого должен находиться в библиотеке проекта, в соответствующем файле: `libs/custom_normalizer.py`.
В базовом классе должны быть определены абстрактные методы для определения даты по имени файла и для чтения записей исходного формата, т.к. эти параметры у всех бирж отличаются. А дальше они работают по сходной, описанной выше, логике.





- исключить:
    - записи не входящие в указанную дату (такие глючные "хвосты" с прошлой даты иногда попадаются)
    - заявки
    - котировки bid/ask
    - служебные события
    - индикативные и справочные цены
    - записи без действительной цены или с нулевым объёмом сделки
    - дубли по идентификатору сделки
    - сообщения об отмене и соответствующие им исходные сделки
    - пустые строки без данных
    - невалидные записи и записи, которые не удалось разобрать или классифицировать
- обработать и применить исправления сделок
